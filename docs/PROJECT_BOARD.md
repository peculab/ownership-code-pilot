# Project workflow

GitHub Issues are the source of truth. A Project board is optional and must not become a second, conflicting status system.

Suggested states:

| State | Meaning |
| --- | --- |
| Ready | Scope and allowed inputs are clear; contributors may propose an approach |
| Claimed | A primary contributor and expected checkpoint are recorded |
| In progress | Work has started; blockers are visible in the Issue |
| In review | A linked Pull Request contains a reviewable result |
| Done | Completion criteria were met and the PR merged |

Use `blocked` only when a named dependency prevents useful progress. Public starter tasks should be designed around synthetic inputs so they can begin without partner files.

Do not assign contributors, deadlines, or commitments without their confirmation. A closed Issue preserves its discussion and does not erase attribution.
