# Ownership Code Pilot

[繁體中文](README.zh-TW.md) · [Claim a task](../../issues) · [Task index](docs/TASKS.md) · [Student quick start](docs/GETTING_STARTED.md)

## Goal

Start from real needs in laundromat communities and test how AI can support content design and trust building. This is a student collaboration pilot with Pecu and Benjamin. Treat customer needs, content effectiveness and AI improvements as questions to investigate, not established results.

## First milestone

Each student completes **one small, demonstrable and verifiable outcome**: a research note, traceable case cards, a content sequence, a draft comparison, a working input-to-draft flow, or a documented reader test. Agree on a scope that fits one week before work begins; no delivery dates are assigned automatically.

## Materials

- [Resource register and access status](docs/RESOURCES.md): meeting notes, approved community list and partner materials.
- [Research](research/), [content](content/), [engineering](src/) and [evaluation](evaluation/).
- Partner materials, community access and NOMA originals are currently **pending confirmation**. No transcript, private group posts or partner files have been copied into this repository.

## Claim a task

1. Open [Issues](../../issues) and read the task's prerequisites and completion criteria.
2. Comment with your motivation, approach, proposed delivery date and help needed.
3. Wait for Pecu/the designated reviewer to confirm scope and assign you. One primary owner and one active task per student; list collaborators in the issue.
4. An issue marked `blocked` can be discussed or claimed, but work requiring missing materials must wait. Record what is missing and who can help.

Students can also [propose a task](../../issues/new/choose) based on an observed problem and supporting evidence.

## Submit work

Create a branch such as `task-1-owner-research`. Submit documents or code through a Pull Request and include `Closes #<issue-number>`. Describe the outcome, validation, evidence and limitations. Address review feedback; merge into `main` only after the designated reviewer approves. A linked issue closes when its closing PR merges into the default branch.

See [CONTRIBUTING.md](CONTRIBUTING.md), [review criteria](docs/REVIEW.md), [board workflow](docs/PROJECT_BOARD.md) and [weekly check-in](docs/WEEKLY_REVIEW.md).

**Never commit passwords, API keys, personal contact details or unapproved partner/community content.** A Private repository still shares files with its collaborators. Use approved source links, minimal paraphrases, anonymized records and access-controlled external materials where needed. Read [data handling](docs/DATA_HANDLING.md).

This repository is Private. Collaborator invitations require each student's and Benjamin's exact GitHub username. No one has been invited automatically.
